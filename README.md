### CSS를 고치면 `?v=` 를 반드시 올리세요 (2026-08-01)

```html
<link rel="stylesheet" href="/assets/base.css?v=260801">
```

GitHub Pages는 CSS에 `Cache-Control: max-age=600`을 붙여 내보냅니다. **주소가 그대로면 브라우저는 새 파일을 받지 않습니다** — 특히 모바일은 더 오래 붙들고 있습니다. 실제로 2026-08-01 한글 줄바꿈을 고친 뒤 서버는 새 CSS를 내보내는데 폰에서는 옛 화면이 그대로였습니다.

`assets/*.css` 중 **하나라도** 고쳤으면 그날 날짜(YYMMDD)로 **21개 링크를 전부** 올립니다. 값은 셋 다 같아도 됩니다 — 목적은 주소를 바꾸는 것뿐입니다.

```bash
grep -rl 'assets/[a-z]*\.css?v=' --include='*.html' . | xargs sed -i 's/\.css?v=[0-9]*/.css?v=260802/g'
```

`/reading/`의 예외 페이지 둘은 CSS를 인라인으로 품고 있어 해당 없습니다.

**CSS를 두 겹으로 나눈 이유**: 주간 회고는 매주 한 장씩 늘어납니다. 색·폰트·카드 스타일을 페이지마다 복사해두면 팔레트를 손볼 때 전부 고쳐야 하고, 매주 자동 생성 비용도 커집니다. 공통은 `base.css`, 회고 전용은 `weekly.css`에 두고 개별 페이지는 내용만 담습니다.

## 이 사이트는 공개입니다

기존 [naru-review](https://github.com/POGNARU/naru-review)와 정반대입니다.

| | naru-review (사적) | 이 사이트 (공개) |
|---|---|---|
| robots | `Disallow: /` 전면 차단 | 없음 |
| 메타 | 모든 페이지 `noindex` | 없음 (검색 노출이 목적) |
| 성격 | 혼자 보는 기록 | 매주 발행하는 콘텐츠 |

**`robots.txt`를 만들지 마세요. `noindex` 메타도 넣지 마세요.** 검색에 잡히는 것이 이 사이트의 목적입니다.

사적 판(naru-review)은 2026-07-31 이후 동결됐고, **2026-08-01에 GitHub Pages를 껐고**(`gh api -X DELETE repos/POGNARU/naru-review/pages`), **2026-08-02에 레포도 비공개로 돌렸습니다**(`gh repo edit POGNARU/naru-review --visibility private`). `pognaru.com/naru-review/`는 404이고, 레포 주소도 이제 열리지 않습니다.

> **왜 껐나**: 그 사이트에는 여과 없는 원본 회고가 올라가 있었습니다. `noindex`로 검색만 막혀 있었을 뿐, 주소를 아는 사람은 누구나 읽을 수 있는 상태였습니다. 파일과 깃 기록은 로컬(`★개발 도구함/naru-review/`)에 그대로 있고, 이관 작업의 재료로 씁니다.

> ⚠️ **Pages를 끄는 것과 레포를 잠그는 것은 다른 문이다 — 둘 다 닫아야 합니다.**
> 8/1에 Pages만 끄고 "닫았다"고 판단했는데, **레포가 public이라 `github.com/POGNARU/naru-review`에서 HTML 20편이 그대로 읽히고 있었습니다.** 8/2에 발견해 비공개로 돌렸습니다.
> 사적인 글이 담긴 레포를 다룰 땐 **`gh api repos/OWNER/REPO --jq '{visibility,has_pages}'`로 두 값을 함께 확인**하세요. 한쪽만 보고 "닫혔다"고 적으면 다음 사람이 그 기록을 믿습니다.
> 배경 원칙: 새벽 글(모닝페이지·몽롱쓰기)은 깃허브·클라우드에 두지 않습니다. 로컬과 OneDrive만.

앞으로 회고는 공개판만 만듭니다. **웹에서 읽히는 회고는 이 사이트 한 곳뿐입니다.**

### 한글 줄바꿈 (2026-08-01)

브라우저 기본값은 한국어를 **음절 단위로** 끊습니다. 그대로 두면 `다음 평 / 일에 답장드려요`처럼 한 단어가 두 줄로 갈립니다. 실제로 현관 카카오 안내 문구에서 이렇게 잘리고 있었습니다.

`base.css`의 `body`가 바탕을 깝니다. **개별 문단마다 다시 걸지 마세요.**

```css
word-break:keep-all;       /* 단어 중간에서 끊지 않는다 */
overflow-wrap:break-word;  /* 대신 긴 영문·URL은 넘치지 않게 끊어준다 */
```

두 줄은 **짝입니다.** `keep-all`만 걸면 끊을 수 없는 긴 토큰(메일 주소·URL)이 화면을 밀어냅니다.

**`/reading/`의 책 표지 팔레트 예외 페이지는 `base.css`를 불러오지 않습니다.** 그런 페이지를 새로 만들면 위 두 줄을 그 페이지 `<style>`의 `body`에 직접 넣으세요. 지금은 `260726-principia.html`·`260730-jeolchang.html` 둘입니다.

**`keep-all`과 `&nbsp;`는 역할이 다릅니다.** `keep-all`은 *한 단어 안*을 안 끊을 뿐, 띄어쓰기로 나뉜 **두 단어 사이는 그대로 끊습니다.** 현관 설명 줄의 `한&nbsp;주씩`·`그&nbsp;결을`이 그래서 필요합니다 — 지우면 그 사이가 갈립니다.

월간 회고의 그래프는 `.scroll-x` 안에서 화면보다 넓게 뻗습니다. 이건 의도된 것이고 본문 가로 넘침이 아닙니다.

**단, 도넛(주제 비중)은 예외입니다 (2026-08-04).** 다른 그래프는 가로로 흘려도 됩니다 — 막대를 하나씩 훑어 읽는 그림이라 스크롤이 자연스럽습니다. 그런데 도넛은 **두 달을 나란히 놓고 견주는** 그림이라, 한쪽이 화면 밖으로 밀리면 비교라는 뜻 자체가 사라집니다. 그래서 `.scroll-x` 대신 `.donuts`로 감싸고 화면에 맞춰 줄입니다.

viewBox도 `640×250` → `420×210`으로 좁혔습니다. 원래 그림은 x축 84~552 구간에만 있어서 **양옆에 170px 가까운 빈 여백**이 있었고, 그 여백까지 `min-width:440px`에 밀려 도넛이 잘려 보였습니다. 가운데 글자(`17` / `11`)는 좁아진 viewBox에 맞춰 함께 올렸습니다 — 여기를 다시 손볼 때 한쪽만 바꾸면 균형이 깨집니다.

**문장은 `display:flex`로 감싸지 않습니다 (2026-08-04).** 기록 스트립의 한 줄 요약 `.days .count`가 flex였습니다. 그러면 텍스트 마디와 `<b>` 강조가 **각각 플렉스 아이템**이 되어, 폭이 좁아질 때 낱말 사이가 벌어지고 세로로 흩어집니다. 폰에서 첫 카드 글자가 줄이 안 맞아 보이던 원인이 이것이었습니다. flex는 칩·아이콘처럼 **덩어리를 나열할 때만** 쓰고, 문장은 보통 블록으로 흐르게 둡니다.

```css
.days .count{ padding-left:15px; text-indent:-15px; }   /* 둘째 줄은 점이 아니라 글자에 맞춰 */
.days .count .dot{ display:inline-block; margin-right:8px; }  /* 7px + 8px = 15px */
```

`weekly.css`를 고치면 개별 페이지 7장의 `?v=` 쿼리도 함께 올려야 합니다. 안 올리면 이미 열어본 사람의 브라우저는 옛 CSS를 계속 씁니다.

## 현관 — 「한 주의 새벽」 블록 (2026-08-01)

설명이 `/weekly/` 안에만 있었습니다. **들어가 봐야 아는 설명은 설명이 아닙니다.** 그래서 현관에 세 층으로 둡니다.

| 층 | 무엇 | 어디로 |
|---|---|---|
| `.latest-note` | 「새벽에 손 가는 대로 쓴 글을 한 주씩 모아, 그 결을 길어 올립니다」 | 링크 아님 |
| `.latest` | 지난주의 새벽 카드 — 눈썹·제목·한 줄 요약 | **그 주 글로 직행** |
| `.more` | 「지난 새벽 모두 보기 →」 알약 | `/weekly/` 목록 |

**「이번 주」가 아니라 「지난주」입니다.** 회고는 늘 **끝난 한 주**를 모아 올립니다. 월요일에 발행하는 글이 가리키는 건 직전 월~일이지 지금 지나가는 주가 아닙니다.

카드 안쪽 글(`weekly/YYMMDD.html`)의 「이번 주 결」·「이번 주의 씨앗」은 **그대로 둡니다.** 그 글 안에서는 그 주가 '이번 주'가 맞습니다. 시점이 다릅니다 — 현관은 오늘에서 과거를 가리키고, 글은 그 주 안에서 말합니다.

**현관 카드는 주간 회고를 지을 때 함께 갱신합니다** (2026-08-01 추가). `jugan-hoego`가 `weekly/index.html` 목록 카드와 **현관 `.latest`를 같이** 손대고, 발행 전 `href`가 그 주 파일과 맞는지 검증합니다. 원래는 목록만 갱신해서, 「지난주의 새벽」이라 적힌 채 몇 주 전 글을 가리킬 뻔했습니다.

**월간 회고는 이 카드를 건드리지 않습니다.** 그 자리는 주간 전용입니다 — 월간을 얹으면 눈썹 문구와 내용이 어긋납니다. `wolgan-hoego`에도 못박아 두었습니다.

`.latest` 안의 `.eyebrow`·`.t`·`.d`는 `<span>`이라 **`display:block`을 반드시 유지해야 합니다.** 빼면 셋이 한 문단으로 이어 붙고 `margin-bottom`도 먹지 않습니다(2026-08-01 발견·수정).

**설명을 카드로 만들지 마세요.** 현관에 누를 상자가 이미 넷(회고 카드 + 정보 카드 셋)이라, 다섯째를 더하면 첫 화면이 '누를 것 목록'이 됩니다. 설명은 누를 것이 아니라 읽을 것입니다.

**`.latest` 카드의 목적지를 `/weekly/`로 바꾸지 마세요.** 목록이 더 친절해 보이지만, 카드에 걸린 제목·요약 문장에 마음이 걸려 누른 사람을 목록으로 떨어뜨리면 방금 걸린 그 글을 다시 찾게 만듭니다. 목록으로 가는 길은 바로 아래 알약이 맡습니다 — 원래 밑줄 링크(`.textlink`)였는데 카드에 눌려 보이지 않아 알약으로 세웠습니다.

**설명 문장의 `&nbsp;`를 지우지 마세요.** `한&nbsp;주씩`·`그&nbsp;결을`입니다. 빼면 좁은 화면에서 그 사이가 갈립니다. `text-wrap:balance`와 함께 두 줄이 고르게 나뉘도록 잡아둔 것입니다.

정보 카드가 셋이라 2열 그리드에서 「책」이 혼자 남습니다. **소개(`/about/`)가 열려 넷이 되면 저절로 맞으니 지금 억지로 손대지 마세요.**

## 새 회고 추가하는 법

1. `weekly/YYMMDD.html`을 기존 회고에서 복제 (파일명은 **그 주 일요일** 날짜)
2. `<head>`의 title·description·canonical·og를 그 주 내용으로 교체. **`<head>`에는 '주간 회고'를 그대로 둡니다**(검색어). 본문에 보이는 말은 「한 주의 새벽」 — 위 이름 규칙을 따르세요
3. 본문 교체 — 기록 스트립 / 새벽의 흐름 / 새벽이 남긴 문장들 / 저녁의 결 / 이번 주 결 / 이번 주의 씨앗 / 핵심 문장 / 저자 블록
   - 저녁 저널이 없는 주는 「저녁의 결」 섹션을 통째로 뺍니다
   - 저녁 타임라인은 `<div class="timeline eve">` — 점이 살구로 바뀝니다 (새벽은 호박)
4. `weekly/index.html`의 해당 월 블록 **맨 위**에 카드 추가. 날짜 배지는 그 주 **월요일**
5. 위 공개 안전 원칙으로 한 번 더 훑기
6. 커밋 & 푸시

**분석 범위는 언제나 월요일~일요일 7일**입니다. 햇살은 한 주를 월요일에 시작해 일요일에 마칩니다.

## 월간 회고 추가하는 법

1. `weekly/YYMM-monthly.html`을 **직전 월간 회고에서 복제** (예: 8월분 → `weekly/2608-monthly.html`). 주간(`YYMMDD.html`)과 구분하려고 `-monthly`를 붙입니다
2. CSS는 `base.css` → `weekly.css` → **`monthly.css`** 세 장. 그래프 스타일은 이미 `monthly.css`에 있으니 새로 만들지 마세요
3. 본문 교체 — 기록 스트립 / 그래프 / 새벽의 흐름(**주차별**) / 저녁의 결 / 새벽이 남긴 문장들 / 이 달의 결 / 이 달의 씨앗 / 핵심 문장 / 저자 블록
4. `weekly/index.html`의 해당 월 블록 **맨 위**에 월간 카드(`.mc`)를 추가. **`.range`는 그 달 전체**(`2026.08.01 — 08.31`)로 둡니다 — 월간 카드의 날짜는 "며칠을 분석했나"가 아니라 **"어느 달이냐"**는 뜻입니다
5. 아래 공개 안전 원칙으로 한 번 더 훑기
6. **푸시하지 말고 확인 요청** (B안)

### 그래프 규칙

**색은 `base.css`의 `--g1`~`--g5`, 비교군은 `--g-compare`.** 월별 계절색을 새로 만들지 마세요.

- **키워드는 날짜 수가 아니라 비율(%)로 견줍니다.** 달마다 기록한 편수가 달라(5월 16편, 6월 19편, 7월 24편) 절대 수치로는 비교가 성립하지 않습니다
- **편수는 폴더를 전부 훑어 세고, 앞 달 페이지의 비교값도 함께 고칩니다.** 2026-08-01에 6월분을 이관하며 원본이 `260617`을 통째로 빠뜨린 것을 발견했습니다(17편 → 실제 19편/18일). 7월 페이지가 그 17편을 비교 기준으로 쓰고 있어 키워드 비율 열한 갈래를 모두 다시 계산했습니다. **한 달을 고치면 다음 달 페이지도 반드시 함께 고쳐야 합니다**
- **결측이 많은 항목은 뺍니다.** 2026년 7월은 글쓰기 시간이 적힌 날이 24편 중 이레뿐이었고 그 이레가 앞뒤로 갈려 있어, 그리면 통계가 아니라 지목이 됩니다
- **어두운 시기가 낀 달은 일별 대신 주 단위로 묶습니다.** 일별 그래프는 특정 날짜의 급락을 그대로 드러냅니다
- 그래프는 `.scroll-x`로 감쌉니다. 좁은 화면에서 **그래프만** 가로로 흐르고 본문은 넘치지 않습니다
