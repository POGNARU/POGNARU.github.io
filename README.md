### `robots.txt` — 감출 주소를 여기 적지 않습니다 (2026-08-22 개정)

**`robots.txt`에 `Disallow:`로 비공개 자리를 적어두던 방식을 걷어냈습니다.** 두 가지가 잘못이었습니다.

**하나 — 안내판이 됩니다.** 이 파일은 누구나 열 수 있고, 사이트를 점검하는 사람이 가장 먼저 여는
파일입니다. 감추려는 주소를 여기 적으면 감추려던 목록을 그대로 알려주는 셈입니다. 설명까지 달아두면
무엇이 있는 자리인지도 함께 알려줍니다. 2026-08-22에 외부에서 실제로 그렇게 열린 것을 확인했습니다.

**둘 — 서로를 무력화합니다.** 두 지시는 역할이 다릅니다.

- `noindex` 메타 — 크롤러가 **읽은 뒤** 색인하지 말라는 지시
- `robots.txt` — 크롤러가 **읽으러 오지도 말라는** 지시

`robots.txt`로 크롤링을 막으면 크롤러는 그 안의 `noindex`를 **볼 수 없습니다.** 두 겹으로 막았다고
여긴 설정이 실은 한 겹을 무력화하고 있었습니다.

**그래서 지금 규칙은**: 검색에서 뺄 자리는 그 레포 HTML 전부에 `noindex` 메타만 넣습니다.
`robots.txt`에는 아무 주소도 적지 않습니다.

> ⚠️ **`noindex`는 검색만 막습니다.** 주소를 아는 사람은 그대로 열 수 있고, 레포가 public이라
> `github.com/POGNARU/<레포>`에서 HTML 원문도 읽힙니다. 무료 플랜에서는 private 레포로
> GitHub Pages를 돌릴 수 없어 생긴 구조적 한계입니다.
>
> **이건 `naru-review`에서 이미 겪은 일입니다**(아래 기록 참조 — 8/1에 Pages만 끄고 닫았다고
> 여겼는데 레포가 public이라 HTML 20편이 계속 읽혔고, 8/2에 발견해 비공개로 돌렸습니다).
> 같은 구조가 `dawn`·`byeol`·`deeper-haetsal` 세 곳에 남아 있었습니다.

### CSS를 고치면 `?v=` 를 반드시 올리세요 (2026-08-01)

```html
<link rel="stylesheet" href="/assets/base.css?v=260801">
```

GitHub Pages는 CSS에 `Cache-Control: max-age=600`을 붙여 내보냅니다. **주소가 그대로면 브라우저는 새 파일을 받지 않습니다** — 특히 모바일은 더 오래 붙들고 있습니다. 실제로 2026-08-01 한글 줄바꿈을 고친 뒤 서버는 새 CSS를 내보내는데 폰에서는 옛 화면이 그대로였습니다.

`assets/*.css` 중 **하나라도** 고쳤으면 그날 날짜(YYMMDD)로 **링크를 전부** 올립니다 (2026-09-13 기준 39개 — base 22 · weekly 14 · monthly 3). 값은 셋 다 같아도 됩니다 — 목적은 주소를 바꾸는 것뿐입니다.

```bash
grep -rl 'assets/[a-z]*\.css?v=' --include='*.html' . | xargs sed -i 's/\.css?v=[0-9]*/.css?v=260912/g'
```

고친 뒤 `grep -rho 'href="/assets/[a-z]*\.css[^"]*"' --include=*.html . | sort | uniq -c` 로 셋이 전부 같은 날짜인지 확인하세요.

`/reading/`의 예외 페이지 둘은 CSS를 인라인으로 품고 있어 해당 없습니다.

**CSS를 두 겹으로 나눈 이유**: 주간 회고는 매주 한 장씩 늘어납니다. 색·폰트·카드 스타일을 페이지마다 복사해두면 팔레트를 손볼 때 전부 고쳐야 하고, 매주 자동 생성 비용도 커집니다. 공통은 `base.css`, 회고 전용은 `weekly.css`에 두고 개별 페이지는 내용만 담습니다.

셋 중 하나만 고치면 기대의 절반만 나옵니다. 지금 값은 아래가 전부입니다.

#### ⓪ 폭 — 한 겹이 아니라 세 겹

| 토큰 | 값 | 쓰는 자리 |
|---|---|---|
| `--w-page` | **1180px** | 화면의 주인. 1440 화면에서 약 83%, 1280에서 92% |
| `--w-mid` | **880px** | 제목 블록·인용·큰 사진·예외 2장 |
| `--w-read` | **660px** | 실제로 읽는 줄. 한글 명조 17px에서 한 줄 약 37자 |

`.shell` 이 `--w-page` 를 두르고, 그 안에서 `.read` / `.mid` 가 좁혀 앉습니다.
**페이지 전체를 상자에 가두는 것과 줄 길이를 지키는 것은 다른 일입니다** — 제목·인용·씨앗은 풀어 두고 문단만 660으로 좁힙니다.
`.wrap` 은 옛 이름 호환으로 남겨 두었고 지금은 읽는 폭으로 동작합니다.

#### ① 글자 크기 8단 (2026-09-09 바닥을 올렸습니다)

`68 / 40 / 24 / 19.2 / 17 / 15.5 / 14.2 / 13` (px)

- 단계 배율 `1.70 / 1.67 / 1.25 / 1.13 / 1.097 / 1.092 / 1.092` — 위 세 단(디스플레이)은 크게 뛰고 아래 네 단(글)은 고르게 걷습니다
- 맨 위 : 본문 = **68 : 17 = 4.0배** (개편 전 2.3배)
- **13px 이 바닥입니다.** 그 아래는 쓰지 않습니다 — 다현씨 지적 그대로 「60~70cm 거리에서 아예 못 알아보겠다」가 12.5px·11.2px 였습니다
- **본문은 17px 입니다.** 아래 세 단만 올리면 16과 15.5가 붙어 층이 사라집니다. 바닥을 올리는 일은 본문까지 한 칸 올려야 끝납니다

| | 값 |
|---|---|
| 모서리 반경 | **2종** — `--r-s` 2px · `--r-m` 4px |
| 행간 | **4종** — 1.28 / 1.55 / 1.75 / 1.95 |

**새 값을 만들지 말고 있는 토큰을 쓰세요.** 한 자리라도 새 반경·새 행간을 넣으면 그날부터 다시 촌스러워집니다.

#### ③ 한 장을 짓는 문법

```html
<main>
  <div class="shell">
    <header class="pagehead">…</header>       <!-- 제목은 넓게, lead 는 좁게 -->
    <section class="sec">                      <!-- 라벨 칸 + 내용 칸 -->
      <div>
        <div class="seclabel"><span class="n">01</span><span class="bar"></span></div>
        <h2 class="sec-title">…</h2>
      </div>
      <div>…</div>
    </section>
  </div>
  <div class="darkband"> … </div>              <!-- 한 장에 어두운 층은 하나만 -->
</main>
```

- `.sec` 는 `15.5rem` 라벨 칸 + 내용 칸 두 칸이고, **860px 아래에서 한 칸으로 접힙니다.** 회고 본문의 `.wsec`, 현관·목록·안내의 `.sec` 가 같은 문법입니다
- **구역 번호(01·02…)는 새로 지은 말이 아니라 구조 기호입니다.** 구역 이름은 전부 그 페이지에 이미 있던 말을 올린 것이고, 라벨에 번호와 이름을 같이 쓰면 바로 아래 h2 와 같은 말이 두 번 나옵니다
- `.seclabel .bar` 의 호박 선은 **라벨 칸 끝까지 뻗습니다.** 세로 획 하나로 두면 「01 |」 처럼 매달려 보입니다 — 선은 어딘가로 뻗을 때 선으로 읽힙니다

#### ④ 화살표와 호버

- **「눌리는 자리」 신호는 한 벌이면 충분합니다.** 호버하면 블록 배경이 `--tint`(살구 70%)로 바뀌거나 제목이 진테라코타로 돕니다. 그래서 `→` 화살표는 전부 걷었습니다
- **남긴 화살표는 방향을 말하는 것뿐입니다** — `←`(뒤로 가기), `↗`(새 창으로 나감). 가르는 기준은 **「이게 방향을 말하는가, 클릭 가능을 말하는가」**
- 블록 전체를 호버 면으로 만들 때 padding 을 주면 아래 형제와 왼쪽 선이 어긋납니다. `box-shadow:0 0 0 1rem var(--tint)` 이면 레이아웃을 한 픽셀도 안 건드리고 면만 바깥으로 넓어집니다

### 한글 줄바꿈 (2026-08-01)

브라우저 기본값은 한국어를 **음절 단위로** 끊습니다. 그대로 두면 `다음 평 / 일에 답장드려요`처럼 한 단어가 두 줄로 갈립니다. 실제로 현관 카카오 안내 문구에서 이렇게 잘리고 있었습니다.

`base.css`의 `body`가 바탕을 깝니다. **개별 문단마다 다시 걸지 마세요.**

```css
word-break:keep-all;       /* 단어 중간에서 끊지 않는다 */
overflow-wrap:break-word;  /* 대신 긴 영문·URL은 넘치지 않게 끊어준다 */
```

두 줄은 **짝입니다.** `keep-all`만 걸면 끊을 수 없는 긴 토큰(메일 주소·URL)이 화면을 밀어냅니다.

**`/reading/`의 책 표지 팔레트 예외 페이지는 `base.css`를 불러오지 않습니다.** 그런 페이지를 새로 만들면 위 두 줄을 그 페이지 `<style>`의 `body`에 직접 넣으세요. 지금은 `260726-principia.html`·`260730-jeolchang.html` 둘입니다.

**`keep-all`과 `&nbsp;`는 역할이 다릅니다.** `keep-all`은 *한 단어 안*을 안 끊을 뿐, 띄어쓰기로 나뉜 **두 단어 사이는 그대로 끊습니다.** 현관 설명 줄의 `한&nbsp;주씩`·`그&nbsp;결을`이 그래서 필요합니다 — 지우면 그 사이가 갈립니다.

월간 회고의 그래프는 `.scroll-x` 안에서 화면보다 넓게 뻗습니다. 이건 의도된 것이고 본문 가로 넘침이 아닙니다.

**단, 도넛(주제 비중)은 예외입니다 (2026-08-04).** 다른 그래프는 가로로 흘려도 됩니다 — 막대를 하나씩 훑어 읽는 그림이라 스크롤이 자연스럽습니다. 그런데 도넛은 **두 달을 나란히 놓고 견주는** 그림이라, 한쪽이 화면 밖으로 밀리면 비교라는 뜻 자체가 사라집니다. 그래서 `.scroll-x` 대신 `.donuts`로 감싸고 화면에 맞춰 줄입니다.

viewBox도 `640×250` → `420×210`으로 좁혔습니다. 원래 그림은 x축 84~552 구간에만 있어서 **양옆에 170px 가까운 빈 여백**이 있었고, 그 여백까지 `min-width:440px`에 밀려 도넛이 잘려 보였습니다. 가운데 글자(`17` / `11`)는 좁아진 viewBox에 맞춰 함께 올렸습니다 — 여기를 다시 손볼 때 한쪽만 바꾸면 균형이 깨집니다.

**문장은 `display:flex`로 감싸지 않습니다 (2026-08-04).** 기록 스트립의 한 줄 요약 `.days .count`가 flex였습니다. 그러면 텍스트 마디와 `<b>` 강조가 **각각 플렉스 아이템**이 되어, 폭이 좁아질 때 낱말 사이가 벌어지고 세로로 흩어집니다. 폰에서 첫 카드 글자가 줄이 안 맞아 보이던 원인이 이것이었습니다. flex는 칩·아이콘처럼 **덩어리를 나열할 때만** 쓰고, 문장은 보통 블록으로 흐르게 둡니다.

```css
.days .count{ padding-left:15px; text-indent:-15px; }   /* 둘째 줄은 점이 아니라 글자에 맞춰 */
.days .count .dot{ display:inline-block; margin-right:8px; }  /* 7px + 8px = 15px */
```

### 왜 이 모양인가

- **골격은 `base.css` 의 `.rowlist` / `.row-item` 을 그대로 씁니다.** 자체 CSS는 날짜 칩 세 줄과 인사형 두 줄뿐이고, **새 색·새 반경·새 행간·새 크기 단은 하나도 만들지 않았습니다**

- **현관에는 구역 번호를 붙이지 않았습니다.** 01·02·03 체계를 흔들지 않기 위해서입니다 — 한 줄짜리를 번호 붙은 구역으로 세우면 무거워 보입니다. 히어로 아래 머리카락 괘선 한 줄 + 살구 칩 「소식」 + 본문 단(17px) 한 문장이 전부입니다
- **살구는 날짜 칩·「소식」 칩에만 있습니다.** 렌더 픽셀로 다시 재니(2026-09-13 한 줄화 뒤) `/news/` **PC 0.588% · 폰 1.879%**, 현관 **0.049%** 입니다. 형광 노랑을 넓은 띠로 깔지 마세요
- **푸터 nav 에 「소식」을 넣었습니다** — 사이트 푸터가 있는 20장 전부입니다(`/news/` 자신은 제외, 표지 팔레트 예외 2장은 원래 푸터가 없습니다). 현관 띠 하나만으로는 하위 페이지에서 소식으로 가는 길이 없습니다
- **동선은 세 단입니다** (2026-09-13 다현씨가 다시 잡으셨습니다) — `현관 소식 띠` → `/news/` → `각 글의 연관 페이지`. 현관 띠는 **칩도 문장도 둘 다 `/news/`** 이고, 안내판으로 가는 길은 소식 목록의 그 행이 가집니다. 띠에 보이는 문장은 **가장 최근 소식의 제목**(미리보기)입니다
- **소식으로 가는 길은 셋입니다** — ①현관 히어로 아래 띠 ②푸터 nav 「소식」 ③현관 03 「묻고 남기기」의 「건네는 말 남기기」 버튼(`/news/#guestbook`). ③은 댓글 자리를 가리키는 유일한 팻말이므로 지우지 마세요 (아래 「문의 동선」 절)
